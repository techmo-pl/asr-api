> Repo-specific guidance for AI coding agents. Inherits global conventions

## What this is

The **canonical source of gRPC API definitions for Techmo ASR**. Proto files
only — no language-specific stubs are committed here. Consumed by every
ASR client/service repo across Techmo (Python, C++, livekit plugins, etc.).

## Stack and entry points

- Language: Protocol Buffers (proto3). No compiled artefacts in-tree.
- Layout under `proto/`:
  - `proto/google/rpc/status.proto` — vendored from googleapis@3daf3792.
  - `proto/techmo/api/status.proto` — Techmo's status type.
  - `proto/techmo/asr/api/{dictation,v1,v1p1,...}/` — versioned ASR APIs
    (see `doc/DOCUMENTATION.md` for the versioning convention).
- `tools/compile_proto.sh` — wraps `protoc` for local C++ stub generation.
- `tools/generate_doc.sh` — regenerates `doc/*-autogenerated.md` using the
  `pseudomuto/protoc-gen-doc` Docker image.
- `VERSION.md` — current package version (single source).

## Setup vs install

Per `README.md`: "the project can be used as-is and does not require any
additional setup". There is **no `setup.sh`, no `install.sh`, and no venv**
to manage in this repo. The techmo split does not apply here because nothing
is built or installed locally — clients pull the proto files via git submodule
and compile them in their own build pipelines.

## Build / test / lint / run

- **Compile (C++ stubs locally):**
  ```bash
  PROTOC=protoc ./tools/compile_proto.sh
  ```
  By default writes `--cpp_out` to the project root. Override with `PROTOC`,
  `PROTOC_OPTIONS`, `PROTOS` env vars (see script).

- **Regenerate API reference docs:** Requires Docker.
  ```bash
  API_VERSION=v1p1 ./tools/generate_doc.sh
  ```
  Default `API_VERSION=legacy`. Output lands in `doc/techmo-asr-api-${API_VERSION}-autogenerated.md`.

- No tests, no lint config, no CI. Verification is downstream (client repos
  compile against the proto and exercise it).

## Versioning convention (load-bearing)

ABNF in `doc/DOCUMENTATION.md`:

```
package-version = major-version [patch-version] [suffix]
major-version   = "v" number          ; v1, v2
patch-version   = "p" number          ; p1, p2 (non-breaking additive)
suffix          = ("alpha" / "beta") number
```

- `v1` → `v1p1` for non-breaking additions.
- `v1p1beta1` → `v1p1` when feature freezes (drop suffix).
- Bump `major-version` only for general breaking overhauls.
- Old stable releases stay in-tree as long as they are serviced.

Do not collapse `v1p1`-style folders into `v1`. Each is an independently
addressable package.

## Repo-specific gotchas

- **No build artefacts ever go in git.** Generated `.pb.cc`, `.pb.h`, `_pb2.py`
  must be produced at consumer-side build time.
- **`tools/generate_doc.sh` requires Docker** and writes back into `doc/`.
  Re-run after any breaking proto edit so the autogenerated reference stays
  current. The script's `sed` step replaces `&#34;` with `"` — preserve that.
- **Vendored `google/rpc/status.proto`** is pinned to googleapis@3daf3792.
  Do not bump it casually; many downstream stubs depend on the exact field
  numbering.
